# Database Setup

The internal MVP stores quotations, approvals, audit events, documents and
email records in a relational database. PostgreSQL is the target for internal
environments; SQLite is supported for local development and automated tests
only.

No credentials are stored in source control. The database URL is read from the
`DATABASE_URL` environment variable at runtime by both the application and
Alembic.

## 1. Install dependencies

```bash
pip install -r requirements.txt        # application
pip install -r requirements-dev.txt    # application + test tooling
```

PostgreSQL additionally needs a driver:

```bash
pip install "psycopg[binary]"
```

## 2. Configure the connection

Copy the example file and edit your local copy. `.env` is git-ignored.

```bash
cp .env.example .env
```

| Variable | Purpose | Default |
| --- | --- | --- |
| `DATABASE_URL` | SQLAlchemy connection URL | `sqlite+pysqlite:///./quotation_ai.db` |
| `DATABASE_ECHO` | Echo SQL to stderr for troubleshooting | `false` |

### Local development (SQLite)

Nothing to configure. With `DATABASE_URL` unset the application uses a local
`quotation_ai.db` file, which is git-ignored.

```bash
export DATABASE_URL="sqlite+pysqlite:///./quotation_ai.db"
```

### Internal MVP (PostgreSQL)

Create a database and a role, then export the URL. Replace every placeholder
with values supplied out of band. **Never commit real credentials.**

```bash
createdb quotation_ai
export DATABASE_URL="postgresql+psycopg://<user>:<password>@<host>:5432/quotation_ai"
```

Prefer supplying the password through your platform's secret store or a
`.pgpass` file rather than an inline URL.

## 3. Run migrations

Alembic reads `DATABASE_URL` from the environment; `alembic.ini` contains no
connection string.

```bash
# Apply every migration
python -m alembic upgrade head

# Inspect current revision and history
python -m alembic current
python -m alembic history

# Roll back one revision, or all the way down
python -m alembic downgrade -1
python -m alembic downgrade base

# Verify the migrations still match the ORM models
python -m alembic check

# Create a new migration after changing app/db/models.py
python -m alembic revision --autogenerate -m "describe the change"
```

Autogenerated migrations that reference the project's portable column types
need `import app.db.types` added to the generated file's imports.

### Convenience schema creation

For local development and the synthetic demo, the Streamlit app calls
`app.services.workflow_session.ensure_schema()`, which creates the tables if
they are absent. This is a convenience only. **Managed environments must use
Alembic**, so that schema changes are versioned and reviewable.

## 4. Test database

Tests never touch a configured database. Each test builds a throwaway
in-memory SQLite database from the ORM metadata via the `engine` fixture in
`tests/conftest.py`, so no environment variable or running server is needed.

```bash
python -m pytest              # whole suite
python -m pytest tests/unit   # domain and codec tests only
```

To additionally exercise the migrations against a real file database:

```bash
DATABASE_URL="sqlite+pysqlite:///./.migration_check.db" python -m alembic upgrade head
DATABASE_URL="sqlite+pysqlite:///./.migration_check.db" python -m alembic check
DATABASE_URL="sqlite+pysqlite:///./.migration_check.db" python -m alembic downgrade base
rm -f .migration_check.db
```

To run the suite against PostgreSQL instead, point `DATABASE_URL` at a
disposable database and override the `engine` fixture. This is not part of the
default suite because it requires a running server.

## 5. Schema overview

| Table | Purpose |
| --- | --- |
| `users` | Internal user accounts |
| `quotations` | Quotation root: identifiers, commercial header, status, version, serialised workflow state |
| `quotation_line_items` | Main products, accessories, services, installation, warranty, freight and other commercial additions |
| `pricing_runs` | Immutable record of each deterministic pricing analysis |
| `technical_validation_runs` | Immutable record of each technical validation |
| `commercial_validation_runs` | Immutable record of each commercial validation |
| `combined_decisions` | Deterministic logical judgement |
| `approval_tasks` | Pending or completed approvals assigned to a named approver |
| `approval_actions` | Individual approval actions, unique per `action_id` |
| `audit_events` | Append-only trail of material workflow events |
| `pricing_data_versions` | Versions of the offline SAP/Excel pricing dataset |
| `generated_documents` | Generated PDFs and exports |
| `email_records` | Generated emails and their delivery outcome |

## 6. Concurrency

`quotations.version` implements optimistic concurrency. Every write asserts the
version the caller last read. If another user has written in the meantime, the
repository raises `QuotationVersionConflictError` instead of overwriting, and
the caller is asked to reload and reapply their change.
